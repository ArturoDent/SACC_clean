-------------------------  Spreadsheet vs baseline  -----------------------------------------------

npm run verify-species-order                       - uses the newest .xlsx in spreadsheets/
node spreadsheets/scripts/verifySpeciesOrder.js    - same
node spreadsheets/scripts/verifySpeciesOrder.js spreadsheets/SomeOther.xlsx [--strict]

Compares the SACCListByCountry spreadsheet (columns E/F = scientific/English name,
G..Y = per-country status codes) against the clean/baseline/*.json sidecars.
Does not read dirty/ - run diffSpeciesList.js first if the question is about
freshly downloaded parts. Prints a summary (first 20 per section) and writes
the full findings to spreadsheets/species-order-report.md, which has:

  - Species out of order       minimal set of displaced species (LIS alignment, so a
                               swap counts once), each shown with a row of context
  - English name mismatches    same scientific name, different common name
                               (typographic apostrophes/dashes are folded first)
  - Scientific name spelling   paired by common name or near spelling, so a typo is
    differences                not reported as one missing + one extra species
  - Only in spreadsheet /      genuinely unmatched species
    Only in baseline
  - Status inconsistencies     the baseline tags a species once for the whole region
                               ("(V)" = vagrant to South America); the sheet tags it
                               per country. Flags species whose regional tag does not
                               follow from the country codes: (V) should be V wherever
                               it occurs, (NB) only NB/V, (IN) only IN/V, (EX) only EX,
                               untagged should be resident (X) somewhere; U is ignored.
                               Some will be deliberate judgments - the country codes
                               are listed so each can be assessed.

Locations link to the species' line in clean/baseline/*.htm. --strict exits 1
when anything is found (for CI); otherwise the exit code is always 0.
